# KeyboardOG 上位机改键 / 改参数工具

WinForms 上位机，用来通过 HID 指令接口修改磁轴键盘的**按键映射**和**磁轴参数**，
以及触发**校准**、**清空映射**和预留的**查询**功能。

界面按 “1 选按键 → 2 选内容 → 3 选值 → 4 执行” 的顺序排布，
键值映射通过**可切换的可视化界面**（键盘 / 鼠标 / 手柄 / 多媒体四个页签）直接点击选择，
下方常驻指令日志（也可另开一个完整日志窗口）方便开发调试。


## 2. HID 通信怎么接的

`HIDComm.dll` 内部用的是**全局状态**（选中的设备句柄、设备表、错误缓冲），
而且 `Hid_ReadResponse` 是阻塞调用。所以：

* 所有原生调用都被放进 `HidTransport` 的**一条专用后台线程**上串行执行（`BlockingCollection` 队列）；
* 界面线程只发异步请求（`await`）和收事件，绝不阻塞、也绝不跨线程碰控件；
* 后台事件通过一个基于 `Control.BeginInvoke` 的 `SynchronizationContext` 切回 UI 线程。

### [上位机补丁] 对复制过来的 HIDComm.cpp 做的唯一修改

`Hid_ReadResponse` 超时分支里，原代码 `CancelIo()` 之后立刻 `CloseHandle + return`，
而读取用的 `buffer` 是**该函数的栈变量**；`CancelIo` 只是请求取消，IRP 未必已经完成，
未完成的 IRP 仍可能往已经失效的栈内存写数据。

本固件目前不会主动上报回应，也就是**每次读都必然走超时分支**，这个隐患会被反复触发，
所以副本里加了一行（源码中用 `[上位机补丁]` 标出）：

```cpp
CancelIo(g_hSelectedDevice);
DWORD cancelled = 0;
GetOverlappedResult(g_hSelectedDevice, &ov, &cancelled, TRUE);   // ← 补丁：等取消真正完成
CloseHandle(ov.hEvent);
```

原始工程 `E:\CPPproject\KeyBoardOG\WindowsGUIIncludes` **没有改动**；
要把补丁合并回去，只需在 `Hid_ReadResponse` 的超时分支里补上那一行。

## 3. 协议速查（全部从固件源码推出，不是猜的）

Report ID `0x04`，数据 8 字节（不含 Report ID）。固件端入口：
`HID.cpp::setup()` 收到 SET_REPORT → `HIDcmd[8]` → `HIDcmdResponseIfChanged()` → `HIDcmdResponse()`。

| idx | SET_MAP (0x01) | SET_PARAM (0x02) | CALIBRATE (0x03) | QUERY (0x04) |
|----|----------------|------------------|------------------|--------------|
| [0] | CMD=0x01 | CMD=0x02 | CMD=0x03 | CMD=0x04 |
| [1] | device | 参数编号 | mode 0=全部/1=单个 | **查询内容 0=键值/1=参数** |
| [2] | 按键 0~13 | 按键 0~13 | 按键 0~13 | 0=全部/1=单个 |
| [3] | offset | 参数值高字节 | — | 按键 0~13 |
| [4] | 操作 0=APPEND/1=OVERRIDE/2=CLEAR | 参数值低字节 | — | 0（空出来的 Byte5） |
| [5] | storageIndex = 该按键的第几个槽 | — | — | — |
| [6] | 0 | 0 | 0 | 0 |
| [7] | **序号（上位机自增）** | 序号 | 序号 | 序号 |

查询内容放在 `[1]`（不占用 Byte5），范围放在 `[2]`，按键号放在 `[3]`。

**`SET_MAP/OVERRIDE` 自带"尾部清零"**：固件写完第 N 个槽之后会调用
`keyMapClearFromEEPROM(key, N+1)`，把这个键 N 后面的槽全部设成空槽
（用 `NO_DEVICE` 宏写）。所以上位机**只需要按顺序发本地列表里有的那几条映射**，
尾部不用再逐条补发空槽 —— 主操作按钮因此只发 N 条指令而不是 12 条。
写完照样回一个 FIN。

### 下位机的回传（全部 Report ID 4、8 字节，"格式与上位机下发的一致"）

| [0] | 含义 | 其余字节 |
|---|---|---|
| `0x05` ACK | 收到了 | [1]=被应答的指令码 [2]=序号 |
| `0x06` FIN | 执行完了 | **[1]=完成的指令码 [2]=按键号（校准进度） [7]=序号**，其余原样回传 |
| `0x01` | 查询结果·一条键值 | [1]=device [2]=key [3]=offset [4]=OVERRIDE [5]=slot |
| `0x02` | 查询结果·一项参数 | [1]=参数编号 [2]=key [3]=值高 [4]=值低 |
| `0xFF` | **设备信息**（独立一帧，之后没有 FIN） | [1]=按键数量 [2]=是否磁轴(0xF0=是/0x0F=否) [3]=编码器数量(0=没有) [4]=设备类型(保留给手台主控) [5..7]=保留(Layout 识别) |

### `CMD_REFRESH (0x07)` —— 改完不用重新插拔

| [0] | [1] | 含义 |
|---|---|---|
| 0x07 | `REFRESH_MAPPING(0x00)` | 让下位机 `keyCodeInit()`：EEPROM 的映射重新载入内存 |
| 0x07 | `REFRESH_PARAM(0x01)` | 让下位机 `keyParameterInit()`：磁轴参数重新载入（只有磁轴键盘有） |

上位机在**每次写操作和每批写入的最后**都自动补一条对应的 CMD_REFRESH
（改映射 → MAPPING，改参数 / 校准 → PARAM），所以**不用再重新插拔键盘**。
查询类指令不会补（它们不改状态）。

### ⚠ 一条指令回两条：ACK + FIN 都要读走

下位机对一条指令先回 ACK（收到）再回 FIN（做完）。上位机**必须把两条都读掉**，
否则残留的 FIN 会被下一条指令当成自己的回应 —— 表现就是"改键丢一半"。
所以现在：

* 每条指令都收到 FIN（并且校验回传确实是这条指令的）才算成功。
  **校验规则**（这地方踩过坑）：ACK 是 `{CMD_ACK, 指令码, 序号, 0...}`，所以比 `[1]=指令码` + `[2]=序号`；
  而 **FIN 是把整条指令原样回传只换 `[0]`**，它的 `[1]` 是 device / 参数编号 / mode，
  **不是指令码** —— 一开始拿 `[1]` 去比指令码，导致 SET_PARAM / CALIBRATE / QUERY 的回应全被误报成"对不上"。
  现在 FIN 改成逐字节比对 `[1..7]`；另外"校准全部按键"时 `[2]` 会被换成逐个按键号，那种情况只比 `[1]` 和 `[7]`。
* 校验不过会在状态栏和日志里报 **「回应对不上：收到 指令0x../序号0x..，期望 …」**，
  这就是"发太快 / 上一条没回收"的信号；
* 收回应的时候如果**第一条就不是本条指令的**，会额外记一条「回应错位」到日志。

### 设备信息（`QUERY` 的 `[1] = 0xFF`）

* 上位机**连接成功后第一件事**就是查设备信息（`04 FF 00 00 00 00 00 seq`），
  收到 `0xFF` 开头的那一帧就算结束（固件不为它发 FIN，所以上位机用
  `isFinalFrame` 把"收到设备信息帧"当成结束条件，不用干等超时）。
* 收到之后上位机会：
  1. **按 `[1]` 的按键数量重建左上角的按键按钮**
     （比本地 `DeviceLimits.KeyCount` 大时夹到上限并提示改配置重编译）；
  2. **按 `[2]` 决定右下角磁轴参数面板的显示 / 隐藏** ——
     非磁轴键盘直接隐藏，右侧可视化选键会自动占满整块区域，也不会再去查参数；
  3. `[3]` 编码器数量、`[4]` 设备类型、`[5..7]` 保留位**先原样存进 `_deviceInfo`**，
     日志里也留一整帧原始数据，留给之后的功能（Layout 识别、手台主控等）。
* 收不到设备信息（老固件 / 超时）时保持本地配置的默认显示，不会卡住。

* **ACK** 在收到指令时立刻回；**FIN** 在处理完成后回。
  校准是阻塞的，所以 FIN 要等用户"按住 → 松开"才来 —— 上位机就是靠它显示"校准中…"。
  全部校准时下位机**每校准完一个键回一个带按键号的 FIN**，最后一个（key = 13）才是整条指令的结束。
* 查询结果一条一个 8 字节报文，上位机可以直接用**下发时同一套字段位置**解析；
  查询结束后同样回一个 FIN。
* 上位机要求"`[7]` 是**下发时**的那个序号"，所以下位机在校准这种阻塞操作前会先对指令做一份快照，
  避免期间 USB 中断改写了 `HIDcmd` 导致 FIN 回错指令。

### device（[1] 字节）—— ⚠ 固件里有两套冲突的编号

| 指令字节 | HIDcmdHandler.h 的叫法 | **Universal.h / KeyManager.h 实际解释为** | 上位机界面 |
|---|---|---|---|
| 0x01 | MAP_TYPE_KEYBOARD | KEYBOARD → `report.keyboardKeys[]` | 键盘 |
| 0x02 | MAP_TYPE_MOUSE | **CONTROLLER → `report.xboxButtons`** | 手柄 |
| 0x03 | MAP_TYPE_GAMEPAD | **MOUSE → `report.mouseButtons`** | 鼠标 |
| 0x04 | MAP_TYPE_CONSUMER | MULTIMEDIA → `report.mediaButtons` | 多媒体 |

device 字节是直接从指令存进 EEPROM、并被 `keyOperation()` 的 `switch` 按 **Universal.h** 的编号解释的，
所以**真正生效的是右列**。本上位机按“实际生效”的编号发送（手柄=2、鼠标=3），
否则鼠标会被打成手柄按键。如果以后要统一命名，改 `HIDcmdHandler.h` 里的 `MAP_TYPE_*` 宏即可，
界面只需要改 `Protocol\ProtocolDefs.cs` 里 `MapDevice` 的取值。

### offset 的取值范围（各设备不同）

| 设备 | offset 含义 | 有效范围 |
|---|---|---|
| 键盘 · 普通键 | HID Usage ID（Keyboard/Keypad page 0x07），直接下发 | 4 ~ 103 → `keyboardKeys[0..12]` |
| 键盘 · 修饰键 | **要换算**：`104 + (usage - 224)`，usage 是 224~231 | 104 ~ 111 → `keyboardKeys[13]` |
| 手柄 | `xboxButtons` 的 bit 下标 = 描述符里第几个按钮 | 0 ~ 15 |
| 鼠标 | `mouseButtons` 的 bit 下标 | 0 ~ 2（左/右/中） |
| 多媒体 | `mediaButtons` 的 bit 下标 | 0 ~ 5（静音/音量-/音量+/播放暂停/下一曲/上一曲） |

**修饰键为什么必须换算**（`SubHID.cpp` 的键盘报文是 14 字节）：

```
keyboardKeys[0..12] = 13 字节普通键（HID usage 0..103，一位一个键）
keyboardKeys[13]    = 1 字节修饰键（usage 0xE0..0xE7 → bit0..bit7）
```

固件 `keyOperation()` 走 `keyboardKeys[offset/8] |= 1 << (offset%8)`。
修饰键要落在 `[13]`，就得让 `offset/8 == 13` → `offset = 13*8 + (usage-0xE0) = 104..111`。
直接把 usage 224~231 发下去会被 `(high<<4)|low` 截断成 `0xC0..0xC7`，高位变成 12 → 落到普通键区，写错位置。

界面上点 Ctrl/Shift/Alt/Win 时，`BindingCatalog.ToWireOffset()` 会自动做这个换算；
映射列表里显示的是 `键盘 Shift_L [device=1, offset=0x69]`（0x69 = 105 = 13*8+1 → `keyboardKeys[13]` bit1）。

### 参数编号（SET_PARAM 的 [1] 字节，来自 Universal.h）

`4 = RT_ACTIVE`、`6 = RT_DEACTIVE`、`8 = UPPER_DEADZONE`、`10 = LOWER_DEADZONE`

参数值 = **满行程的千分比**（`EEPROM 值 / 1000 × (bt_maximum - bt_minimum)`），
固件只接受 `10 < value < 980`，即**有效区间的 11~979**，超出会被静默忽略（无报错）。
界面上直接显示 “40 / 1000 = 满行程的 4.0%”。

## 4. 固件侧的坑（重要，验证前一定要看）

1. **`HIDcmdResponseIfChanged()` 会丢弃重复指令。**
   它对上一条指令做 `memcmp`，只有 8 字节**不完全相同**才执行。
   连续发两条一模一样的指令，第二条会被静默忽略。
   → 上位机在指令的保留字节 `[7]` 写了一个自增序号，保证每条指令都唯一
   （`ProtocolDefs.cs` 的 `CommandBuilder.NextSequence()`，日志的“数据”列可以看到它递增）。

2. **`keyOperation()` 的 `switch` 没有 `default` 分支。**
   ```cpp
   while (key_map[i][key_map_addr][DEVICE] != 0) {
     switch (...) { case KEYBOARD: ... key_map_addr++; break; ... }
   }
   ```
   一旦 EEPROM 里出现固件没处理的 device 值（协议里定义的
   `MAP_TYPE_CONTROLLER_XAXIS_*` / `MOUSE_X` / `MOUSE_Y` / `LEFT|RIGHT_TRIGGER`，即 5~12），
   `key_map_addr` 不会自增 → **设备会在这个 while 里死循环**，键盘直接卡死。
   → 本上位机**不提供**这些轴/扳机映射类型（手柄页上的 LT/RT 画成灰色“未实现”）。
   如果以后要支持，必须先在固件里给 `switch` 加 `default: key_map_addr++; break;`。

3. **键盘修饰键要换算 offset（不是不能用）。**
   修饰键的 HID usage 是 224~231，但固件的下标是 `offset/8`，
   要落到报文的第 14 字节 `keyboardKeys[13]`（修饰键字节）就必须下发 `104~111`。
   详见上面“offset 的取值范围”一节；上位机已自动换算，界面上修饰键可以正常点选。

4. **APPEND / OVERRIDE 只写 EEPROM，不刷内存。**
   `keyCodeAddToEEPROM()` / `_keyCodeSetToEEPROM()` 写 EEPROM 后并没有更新运行中的 `key_map[][]`；
   只有 `keyCodeInit()`（启动时调用，或 CLEAR 指令内部调用）才会重新载入。
   → **改完映射必须重新插拔 / 复位键盘才生效**，界面在执行后会明确提示这一点。

5. **CLEAR 是清空整张表，不能只清一个键。**
   `case MAP_DO_CLEAR:` 只做 `EEPROM.write(STORAGEDKEYCOUNT_POSITION, 0); keyCodeInit();`
   —— 不带按键参数，清掉的是全部 14 个键。
   → 所以“写入一份完整映射”的做法是：**CLEAR → 按 0~13 顺序把所有映射重新 APPEND**
   （就是界面上的“清空全部映射 (CLEAR)”按钮）。CLEAR 之后运行中的映射表是空的，
   同样要重新插拔才会载入新写入的内容。

6. **OVERRIDE 的 storageIndex 是「该按键的第几个映射槽」（0 起）。**
   新版存储把映射区按按键切成固定区域（每个按键 `KEYMAP_SIZE_PER_KEY = MAXIMUM_BINDABLE_KEY * 2` 字节，
   每个映射 2 字节 `(device, offset)`，按键之间依次紧挨，
   起始位置 `KEYMAP_START_POSITION = BUTTONCOUNT * PSOOSK`），
   所以 OVERRIDE 直接写这个按键自己的第 N 个槽，**不影响别的按键**，上位机列表里的槽号可以 1:1 对应。
   注意两点：① 读取遇到空槽（`device == 0`）就停，所以**槽位中间不要留空洞**；
   ② 写入仍然只落 EEPROM，要重新插拔才生效（见第 4 条）。

7. **校准是阻塞的，而且需要人工配合。**
   `calibrateKey()` 里有 `while` 循环，要等到该键的采样值先低于 260 再高于 260
   （也就是**必须先按住、再松开**）才返回；`calibrateAll()` 会对 14 个键依次这么做。
   校准期间固件主循环被占住，**其它指令不会被处理**。
   → 界面在点“校准全部”时会提示需要预留约 14 × 每键 2 秒的时间。

8. **查询 / ACK / FIN 已经接上了。**
   固件在 `HIDcmdHandler.h` 里回 ACK（收到）和 FIN（做完），
   查询结果逐条回传，全部走 Report ID 4、8 字节的输入报文。
   → 上位机连接成功后会自动跑一次全局查询（先键值、再参数）把键盘现状同步过来；
   如果日志里一直是“超时”、收不到 ACK/FIN，说明固件不是这一版。

9. **没写过的 EEPROM 读出来是 `0xFF`，必须当成空槽。**
   `device` 只可能是 `KEYBOARD..MULTIMEDIA`(1~4)，所以固件用
   `keyMapSlotIsEmpty()`（`!(device >= KEYBOARD && device <= MULTIMEDIA)`）
   统一判定空槽：0（正常空槽）、0xFF（擦除态/没写过）、旧格式残留数据全都算空槽。
   三个读路径都走这个判定：`keyCodeGetFromEEPROM`（开机载入）、
   `keyMapGetFromEEPROM`（查询上传）、`keyCodeAddToEEPROM`（找空槽）。
   → **不这么做的话**：新板子/换过存储布局的板子，映射区是 `0xFF`，
   会被当成 `device=255, offset=255` 的映射读出来 —— 查询会导进一堆垃圾，
   而且 `keyOperation()` 遇到 `device=255` 这种非法值会卡死（老版本没有 `default` 分支）。
   上位机侧也做了一道过滤：设备号不在 1~4 的查询结果直接丢弃。

10. **EEPROM 容量（新版固定分区）：**
   参数区 `0 ~ BUTTONCOUNT*PSOOSK-1`（14×12 = 168 字节），
   映射区从 `KEYMAP_START_POSITION = 168` 开始，每个按键 `MAXIMUM_BINDABLE_KEY*2` 字节，
   按键依次紧挨。以 `MAXIMUM_BINDABLE_KEY = 12` 为例：
   映射区 14×24 = 336 字节，总占用 504 / 1024 字节。
   固件不做越界检查，改按键数 / 最大映射数时请自行核算（`Universal.h` 里有注释）。

## 5. 界面布局与使用流程

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 设备：[下拉框=只列指令接口] [刷新] [连接] [● 设备未连接]   [设置…] [指令日志…] │
│ 连接详情 / 队列：0                                                            │
│ 状态栏（最近一条指令的结果）                                                  │
├────────────────────────┬─────────────────────────────────────────────────────┤
│ 1. 选择要修改的按键      │  ┌ 键盘 │ 鼠标 │ 手柄 │ 多媒体 ┐                    │
│   [0][1]…（绿=一致/红=改）│ │   可视化选键：左键替换 / 右键·Shift+左键追加 │    │
│  绿=与键盘一致 红=本地有改动│ └──────────────────────────────────┘             │
│   ┈┈ 下方预留区 ┈┈      │  提示：当前按键 / 已选 N/12 / 鼠标手势               │
│ 2. 按键映射列表          ├─────────────────────────────────────────────────────┤
│  按键 #N：n/12 [清空全部按键映射]                                             │
│  （12 行多一点，美观）    │  磁轴参数 / 校准（当前 #N）                         │
│  [↑][↓][删除][清空该键] │  校准按键+说明 │ 写入范围(单选/多选) │ 4×[滑块+值框] │
│        ……（空）……        │  [全选/全不选][重新读取磁轴参数]   │ [写入参数]     │
│  [重新读取映射（放弃改动）]（贴底）   │  （上面那行提示 = 参数说明 / 校准状态）  │
├────────────────────────┴─────────────────────────────────────────────────────┤
│ ③⚠危险[清空] │ (提示) │ ②[写入全部按键映射] │ ①写入当前按键映射（主操作）│
└──────────────────────────────────────────────────────────────────────────────┘
```

* **最上面**是设备连接区（+ 右上角的“设置…”和“指令日志…”两个按钮）。
  下拉框**只列指令接口**（UsagePage=0xFF00 / Usage=0x01）的设备，触摸板/鼠标之类不再混在里面；
  万一一个都没匹配到会退回列出全部并说明原因（不然没法连）。
  右边那个**● 设备未连接**（红）/ **● 设备已连接**（绿）是醒目提示。
  注意：下拉框是过滤过的，所以连接时用的是"显示项 → 原生设备表下标"的映射，不会连错。
* **按键按钮的颜色表示"本地和键盘是否一致"**：
  **绿 = 一致**（刚查询同步过、或刚写入成功）· **红 = 本地有改动还没写入**；
  当前选中的按键用更粗的深蓝边框区分。
  单键写入成功后**只把这一个键标绿、且故意不做查询** —— 全局查询会把其它按键的本地内容一起覆盖掉。
* **“设置…”** 打开参数设置子窗口（**模态**：独占聚焦、一直在主界面前方，
  不点确定/取消回不到主界面）：
  | 参数 | 默认 | 说明 |
  |---|---|---|
  | 发送频率 | 500 Hz | 批量写入时两条指令之间的最小间隔（500Hz ≈ 2ms 一条）。键盘 1kHz 上报时发太快会丢指令 |
  | 回应超时 | 500 ms | 等 ACK / FIN 的最长时间 |
  | 等 FIN 再发下一条 | 开 | 关掉会连续快发，容易丢指令 |
  「取消」完全不生效（在副本上改，只有「确定」才写回并保存）；还有「恢复默认」。
  参数存在 **exe 同级目录的 `KeyboardOG.settings.ini`** 里，下次启动自动读回来；
  文件不存在时用默认值并**自动生成**，删掉它就恢复默认。
* **左侧上方**是按键选择；下面留了一块**预留区域**，将来可以换成带状态显示 / 可变样式的按键选择器。
* **左侧下方**是映射列表，拉长到 12 条能一屏看完。
* **右侧上方**是可视化选键（四个页签）。
* **右侧下方**是**磁轴参数 / 校准**（独立 UserControl `HallParamControl`），默认显示。
* **最下面**是横向的执行条，按风险分成三组，**遵循"右手为主手"，主操作放在最右侧**：
  最左是 ③ ⚠ 危险操作（清空全部映射，按钮特意做小、单独隔开）·
  中间是提示文字 · 右边是 ② 写入全部按键映射 · **最右是 ① 写入当前按键映射（主操作，最大最显眼）**。
* **主操作怎么工作的**：新存储结构下每个按键有自己一块固定的 EEPROM 区域，
  所以「写入当前按键映射」= 对这个按键的 0~11 号槽各发一条 `SET_MAP/OVERRIDE`
  （本地列表里的映射写进对应槽，多出来的槽写 `device = 0` 变成空槽）。
  它**只动这一个键**、不影响别的键，也不需要先清整表，因此取代了原来的 APPEND/OVERRIDE
  两个按钮和「清整表再重写」的同步方式。
  尾部的空槽由键盘自己清零，所以只发本地列表里有的那几条指令；
  写完自动补一条 `CMD_REFRESH`，**不用重新插拔键盘**。
* **右下角「键盘当前值」**是连接后自动查询回来的四个磁轴参数，竖着排一行一个（不会被截断）；
  切换参数种类时，**查询到的当前值会直接填进值框**，用户是在键盘的真实数值上改，
  而不是从默认值 40 开始改。
* **指令日志**是右上角按钮打开的子窗口：非阻塞、不抢焦点（重写了 `ShowWithoutActivation`，
  重复点按钮也不会 `Activate`），底部有一条“发送 / 接收确认 / 已完成 / 超时 / 失败”的统计条。
  关闭只是隐藏，不影响主窗口。

操作顺序：

1. **刷新设备** → 选带 `★指令接口` 的那一项 → **连接**。
   （`★` 只代表该设备顶层集合是 `UsagePage=0xFF00 / Usage=0x01`，触摸板之类也可能命中；
   看下拉框里的 `#实例号` 确认是不是你的键盘。两边都带 `&` 的路径现在会原样显示。）
2. **连接成功后会自动查询同步**：先读全部键值、再读全部参数，
   左侧列表和右下角「键盘当前值」都会被填上键盘里的真实内容
   （本地没写入的临时改动会被键盘上的数据覆盖）。
3. 点按键编号（0~13）→ 右上页签里点要映射到的按键（最多 12 条）。
   修饰键（Ctrl/Shift/Alt/Win）也能点，offset 会自动换算。

   **鼠标手势**（四个选键控件统一）：

   | 点到的按键 | 操作 | 行为 |
   |---|---|---|
   | **已经在列表里** | 左键 / 右键 / Shift+左键 | **只删掉它自己**（"点已有的映射 = 取消它"这条认知始终成立，不会牵连别的条目） |
   | 新映射 | **左键** | **替换**左侧列表里**选中的那一条**（想只留一个映射时不用先删再加）；列表里没选中时就是追加 |
   | 新映射 | **右键** / **Shift+左键** | **追加**一条 |

   替换只动选中的那一槽、**不会碰别的条目**；替换完选中的槽位保持不变，追加完会自动选中新加的那条。
4. 映射列表上方/下方的几个按钮：
   - **清空全部按键映射**（红框，在“按键 #N：n/12 条”右边）：**点两次才生效**，
     第一次点文字变成「再次点击以确定清除」（几秒不点会自动复原），再点一下才清空本地全部映射；**不弹窗**。
   - **清空该键**：清空当前按键的本地映射，**不弹窗**。
   - **重新读取映射（放弃改动）**：重新查一遍映射，本地改动全部丢弃、还原成键盘上的内容（按键全部变绿）。
   - **重新读取磁轴参数**：重新查一遍磁轴参数，值框/滑块换成键盘上的真实值。
   （映射列表高度固定成"正好 12 行"，以后最大映射数调大了右侧会自动出滚动条。）
5. 执行：
   - ① **“写入当前按键映射”**（主操作）：把当前键的映射整片写进去
   - ② “写入全部按键映射”：所有按键各写一遍（本地没有的键会被清空）
   - ③ “清空全部映射 (CLEAR)”：危险操作，单独隔离，带二次确认
6. 磁轴参数模块（在选键区下面那一条）：
   * **校准**（左）：校准当前按键 / 校准全部按键；校准时**上面那行提示会变成校准状态**，
     全部校准时逐个回报进度，校准完 2 秒后还原成参数说明。
   * **写入范围**（中）：按键按钮和左上角那排一模一样，
     **左键 = 单选**（只留这一个键，右边滑块立刻变成这个键的值）、
     **右键 / Shift+左键 = 多选**（累加/取消，用于批量）。
     **底色表示选没选中（蓝 = 选中，白 = 没选中），数字颜色表示参数状态（绿 = 和键盘一致，红 = 改过还没写入）**
     —— 左上角那排按键用同一套约定。
     旁边还有「全选 / 全不选」和「**重新读取磁轴参数**」（重新读一遍，放弃参数改动、颜色复位）。
   * **四个参数**（右）：每个参数一个**垂直滑块 + 一个值框**（拖滑块或直接填数字双向联动），
     上面显示参数名和「键盘 xx」（键盘上的真实值）。
     **RT 触发行程 / 上死区 的滑块是「上=最小值、下=最大值」**，另外两个是常规方向。
   * **「将四个参数发给选中按键」**（最右）：把四个参数一起发给范围内的按键（逐个发送），
     写完自动刷新。**按按键分别判定成功**：四个参数都写成功的按键数字才恢复成绿色，
     没成功的仍然是红色，并且中间那行提示会明确写出"有 N 条没写成功（没收到正确的 FIN）"。
   * 一个都不选 = 只写主界面当前选中的那个按键。
   校准点“校准当前按键 / 校准全部按键”，状态栏会显示“校准中…”，
   全部校准时键盘每完成一个键就回报一次，状态栏跟着更新，收到最后一个 FIN 才算完成。
6. 排查问题点右上角“指令日志…”，查询结果在日志里显示成“查询结果·键值 / 查询结果·参数”。

### 复用到别的键盘（例如 6 键小键盘）

只改 `Protocol\ProtocolDefs.cs` 里的 `DeviceLimits.KeyCount`（按键按钮是按它动态生成的），
再把右侧的可视化选键控件换成对应布局即可；`HallParamControl` 和整个通信层不用动。
`MaxBindingsPerKey` 对应固件的 `MAXIMUM_BINDABLE_KEY`。

## 6. 已经验证到什么程度

在**没有键盘硬件**的机器上跑通的（用真实的 App 进程 + 真实控件交互截图确认）：

* 原生库编译、7 个导出符号、`Hid_EnumerateDevices` 枚举成功并正确解析出
  产品名 / VID / PID / UsagePage / Usage / 指令接口标记 / 设备实例号（结构体 Marshal 正确）。
* 设备列表、连接/断开、状态栏、队列计数、日志（信息/发送/接收/失败/超时）都正常。
* 可视化选键：键盘、鼠标（左/右/中键）、手柄（B1~B16，LT/RT 灰色“未实现”）、多媒体都能点击加入映射列表；
  **四个设备类型的 device 编号分别是 1 / 2 / 3 / 4，与固件运行时的解释一致**。
* **修饰键已验证**：点左 Shift → 映射列表显示 `键盘 Shift_L [device=1, offset=0x69]`，
  0x69 = 105 = `13*8 + 1` → 正好是 `keyboardKeys[13]` 的 bit1（LeftShift）。
* 选键控件的文字不再重叠（主标题与 bit 下标分区绘制，窄控件自动降字号）。
* 8 字节指令编码已逐字节核对（日志“数据”列），例如
  `SET_MAP/APPEND 按键#0 += 键盘 A` → `01 01 00 04 00 00 00 01`
* “写入当前按键映射” = 该键 12 个槽各一条 `SET_MAP/OVERRIDE`（序号递增）跑通。
* 查询指令字节已核对：全局键值查询 = `04 00 00 00 00 00 00 seq`
  （CMD=0x04 / [1]=QUERY_MAPPING / [2]=CQ_ALL / [3]=0 / Byte5 空出来）；
  单键校准 = `03 01 00 00 00 00 00 seq`。
* 可视化选键的**再点一次取消选中**：点 A → 列表出现 `键盘 A [device=1, offset=0x04]`、
  按键变绿；再点 A → 列表清空、颜色复原、状态栏提示“移除映射”。
* 校准状态显示：发送失败/收不到 FIN 时状态栏给出明确提示并解锁按钮（已用真实进程验证）。
* **选键控件的鼠标手势**（真实进程 + 真实点击验证过）：
  左键点 A → `[A]`；再左键点 S → **替换**成 `[S]`；Shift+左键点 D → `[S,D]`；
  此时左键点已有的 S → **只删掉 S**，D 原样保留 → `[D]`；
  右键点新映射 A → 追加 `[D,A]`；再右键点已有的 A → 只删掉 A → `[D]`。
* **设置子窗口**（真实进程 + 真实点击验证过）：
  第一次启动自动生成 `KeyboardOG.settings.ini`（500/500/1）；
  把文件改成 `250/800/0` 再启动，窗口里读回来的就是 250Hz / 800ms / 不勾选（截图确认）；
  点「恢复默认」再点「取消」→ **文件一个字没变**（取消不生效）；
  点「恢复默认」再点「确定」→ 文件变成 `500/500/1`、子窗口自动关闭、状态栏显示已生效并保存；
  再次启动读回来的就是 500/500/1。
* **设备信息 → 界面联动**：用一个真的 `Form1` 实例注入构造出来的设备信息帧验证过
  （`_diag\DevInfoTest.cs`）：
  `6 键磁轴` → 按键按钮 14→6、磁轴面板保持显示；
  `8 键非磁轴` → 按键按钮 14→8、磁轴面板 True→False、右侧选键区高度 530→708（自动占满）；
  `14 键磁轴` → 14 个按钮；`收不到设备信息` → 保持 14 键 / 面板显示，不卡住。
  另外验证了普通键值帧不会被误判成设备信息。
* 发送失败路径（`HidD_SetOutputReport failed`）能正确显示在日志里。
* 日志子窗口：能打开、能导出 CSV、能清空。导出默认落在「文档」目录（exe 可能装在没写权限的地方），
  目标文件是**只读**时会自动去掉只读属性再写；万一目标目录没权限，会自动改存到「文档」并告诉用户新路径。
  **打开后主窗口仍然是前台窗口（`GetForegroundWindow` 实测未变）**，即不抢焦点、不阻塞。

**还需要你在真机上确认的**：

* `HidD_SetOutputReport` 对**键盘**的 Report ID 4 是否返回成功（本机上用的是一台
  触摸板的厂商集合，它没有 Report ID 4 的 OUTPUT 报文，所以必然失败）。
* 改完映射重新插拔后，键盘的实际输出是否符合预期
  （尤其手柄 B1~B16 和游戏里的对应关系 —— 描述符只声明了 16 个按钮，
  界面上的 `(A)(B)(X)(Y)` 是按 Xbox 习惯标注的，若不一致只改按钮文字即可，协议不受影响）。
* 校准：按住/松开的采样阈值 260 是否适合你的磁轴（`cali_threshold_position`）。

## 7. 签名 / 消除软件转移后的警告

见 [signing\README.md](signing/README.md)。里面区分了三种警告的来源（网络标记 / 未知发布者 / SmartScreen 信誉），
并给了对应的脚本：

| 脚本 | 干什么 | 要管理员吗 |
|---|---|---|
| `Unblock-Files.ps1` | 去掉「来自其他计算机」标记（**转移后最常见的警告就是这个**） | 不用 |
| `Make-Cert.ps1` | 生成 **CN=LGGZ** 的自签名代码签名证书（.cer + .pfx，密码 123456） | 不用 |
| `Sign-App.ps1` | 给 exe / dll 签名（带时间戳），**每次重新编译后都要跑一次** | 不用 |
| `Install-Trust.ps1` | 目标机器上信任 LGGZ（受信任的根 + 受信任的发布者）+ 解除阻止 | 要（会自己提权） |
| `Check-Sign.ps1` | 查看签名状态、发布者、是否还有网络标记 | 不用 |

⚠️ 自签名证书只能消掉「未知发布者」，**消不掉 SmartScreen 的信誉拦截**；
要彻底没有那个提示只能买 CA 签发的正式代码签名证书。

## 8. 明确没有做的事

* 没有做映射/参数的**本地持久化**（关掉程序就丢了），需要的话再加一个 JSON 读写即可。
* 没有做**读回当前映射**：固件端还没有实现查询响应。
* 没有支持轴/扳机映射（`MAP_TYPE_CONTROLLER_XAXIS_*` 等），原因见坑 #2。
* 没有改动 `KeyboardOG\` 之外的任何工程；
  `HIDComm.cpp/.h` 是**复制**到工作区里编译的（只有那一行 `[上位机补丁]`）。
* 磁轴参数的“最大值/最小值”（EEPROM 里的 `MAX_VALUE`/`MIN_VALUE`）是校准写入的，
  没有做成手动可编辑项。
